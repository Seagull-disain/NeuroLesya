# Інтеграція компонентів НейроЛесі

Цей документ описує, як основні компоненти архітектури взаємодіють між собою.

## Загальний потік

**Користувач → Interface → Core/Input → Intent → Context → Orchestrator → Tasks/Tools/Skills/Projects → Response → Memory → Self-Improvement**

**Identity & Continuity** забезпечує наскрізну безперервність контексту, конфігурації та версій системи.

## Взаємодія компонентів

### Core ↔ Memory
Core запитує лише релевантну пам'ять. Memory не повинна самостійно визначати відповідь користувачу.

### Core ↔ Personality
Core отримує активну конфігурацію особистості та режиму перед формуванням відповіді.

### Core ↔ Projects
Для запитів, пов'язаних із проєктом, Core отримує контекст активного проєкту. За неоднозначності контексти не змішуються.

### Core ↔ Tasks
Складне завдання передається менеджеру завдань для декомпозиції, виконання та перевірки.

### Orchestrator ↔ Tools
Orchestrator викликає інструменти через визначений контракт. Інструмент повертає результат або помилку, але не керує всією системою.

### Skills ↔ Tools
Навичка може використовувати один або кілька інструментів, але отримує лише необхідні дозволи.

### Memory ↔ Self-Improvement
Результати, помилки та зворотний зв'язок можуть бути сигналами для аналізу. Сам факт збереження досвіду не означає автоматичну зміну системи.

### Self-Improvement ↔ Identity & Continuity
Прийняті зміни повинні бути версійованими, щоб розвиток системи можна було відстежувати та, за потреби, відновлювати попередній стан.

## Принцип залежностей

Нижчі спеціалізовані компоненти не повинні створювати прихованих циклічних залежностей. Core/Orchestrator координує взаємодію, а компоненти мають чіткі контракти.

## Контроль змін

Будь-яка зміна, що впливає на код, дозволи, політики, пам'ять або ідентичність системи, повинна бути відтворюваною та перевірюваною. Критичні зміни потребують рішення людини.

## Статус

Це інтеграційна модель початкового прототипу. Вона уточнюватиметься після появи першої програмної реалізації та тестів.
