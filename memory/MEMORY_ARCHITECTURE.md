# Архітектура пам'яті НейроЛесі

## Призначення

Пам'ять забезпечує збереження та використання релевантного контексту між повідомленнями, завданнями та сесіями.

Головний принцип: НейроЛеся не повинна накопичувати все підряд. Вона має визначати, що є корисним для майбутньої роботи, де це зберігати та коли використовувати.

## Рівні пам'яті

### 1. Short-Term Memory
Поточний діалог і тимчасовий контекст активного запиту.

### 2. Working Memory
Активні завдання, проміжні результати, прийняті рішення та поточний стан роботи.

### 3. Long-Term Memory
Стабільна інформація, яку дозволено зберігати для використання в майбутніх сесіях.

### 4. Project Memory
Контекст конкретного проєкту: цілі, рішення, файли, етапи, відкриті питання та історія роботи.

## Memory Manager

Менеджер пам'яті відповідає за:

- визначення інформації, яку доцільно зберегти;
- класифікацію пам'яті за рівнем;
- пошук релевантної інформації;
- передачу потрібного контексту ядру;
- оновлення застарілих записів;
- видалення інформації за запитом користувача.

## Потік

**Запит → пошук релевантного контексту → формування Context → виконання → оцінка нового досвіду → збереження за правилами пам'яті.**

## Принцип користувацького контролю

Користувач повинен мати можливість переглядати, змінювати та видаляти збережену інформацію.

Система не повинна приховано створювати критичні або чутливі записи без відповідного механізму контролю.

## Релевантність

Під час формування контексту перевага надається інформації, яка безпосередньо стосується поточного запиту, активного проєкту та поточного завдання.

Повна пам'ять не повинна автоматично передаватися моделі.

## Майбутня реалізація

Архітектура може бути реалізована через абстракцію сховища пам'яті. Це дозволить у майбутньому змінювати конкретну технологію зберігання без перебудови ядра НейроЛесі.
